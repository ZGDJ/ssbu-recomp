# Rollback continuation router

Continue OpenSmash using [AGENTS](../AGENTS.md), the [ledger](../milestones/README.md) usage/priorities and selected task/dependencies, the [current handoff](ROLLBACK_HANDOFF.md), and the [project skill](../.agents/skills/opensmash-gameplay/SKILL.md). Recheck branch, tree and origin before edits. Read linked evidence on demand; this file deliberately duplicates no current status, test counts or package identity.

Advance the selected gameplay outcome through a cohesive implementation batch. Reuse accepted unchanged evidence, define exclusive parallel ownership, and let Astra integrate and serialize native execution. Honor requested model/effort and verify the actual selection. Follow [workflow](AGENT_WORKFLOW.md) and [validation](VALIDATION.md); historical commands are not current admission. Never bypass identity/admission, disable verification to obtain a seal, or restart a stopped batch without the user's instruction.

Complete authorized implementation and relevant tests, update evidence/index/ledger/handoff at the integration boundary, validate documents, commit/push and verify clean local/remote agreement. If blocked, report the exact unresolved prerequisite and resolving action; do not substitute another inventory for known implementation work.

## User continuation

In the same working conversation, say: `Continue OpenSmash toward the next bounded rollback gameplay experiment using the project skill and current ledger. Complete the smallest useful batch, then run when its required gates pass.`

For a fresh Astra conversation, invoke `$astra-prompt` in the existing conversation and paste its generated prompt into the new one opened on this repository. That skill prepares a current assignment; it does not execute it. If the personal skill is unavailable, use the same continuation sentence with this repository path and ask the agent to read AGENTS.md and this router. The project skill is tracked in the repository; the personal prompt skill is installed outside Git.

Use the workflow's smallest-experiment rule. New prerequisites must address a named unsafe action or false conclusion; missing in-scope code should be completed. Existing native gates and user-owned restarts remain binding. No broad re-audit or newly generated prompt is needed for ordinary continuation within the same conversation.
