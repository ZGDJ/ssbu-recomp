## Defect, callers and invariant

`nnsdk2.c` overrides `FreeAddressRegion`, bypassing the earlier checked SDK release. Successful reservation release can also recycle an address retained by snapshot windows, extras or retired ranges. A release-result check alone cannot preserve that ownership. Both SDK address-release handlers and `FreeMemoryBlock` now use one checked helper; published pthread stack and non-reserved NRO release use it too. `save` pins guest reservations before its first `collect`. An SRW lock serializes that pin with release and both cache notifications. After pin, release terminates before cache/OS mutation; before pin, OS failure terminates before post-notification/return. Pin persists for the process, including refused saves and empty rings, because those do not establish retirement of all tracking owners. This is an explicit conservative restriction, not successful emulation of reservation destruction. No claim of observed battle-failure causality.

The temporary TLS allocation in `fiber_main` is released before publishing `o->fctx`; its actual borrowed TLS is assigned before publication. Prepublication allocation cleanup and self-test/private snapshot backing are distinct from released published guest storage. Native continuation lifetime and logical module teardown remain M7.1/M7.2; decommit/notification concurrency and full quiescence remain M2/M4. The guard does not certify those paths.

`SSBU_MEM_KEEP` had unchecked query coverage, skipped readonly pages and unmarked zeroing. Nonzero requests now explicitly terminate at initialization before memory mutation; the unsafe clearing branch is removed. Supported unset/zero retains normal checked decommit. This restriction applies to forward-only execution too. It is supported-path isolation by code, not an assumption that environment zero alone repairs optional behavior.
