## Concrete findings for integration

1. **Input equivalence is not yet an enforced paired gate.** prepare.py:34 copies the same baseline twice, then overlays each package. That is a useful setup, not evidence that all effective inputs match. run_trial.py:23 captures each identity, but never compares the two. battle_identity.capture validates each package against its source and inventories DLLs; it does not assert paired equality or prove which DLL loaded. Do not report candidate association until the inventory delta is explained field by field. Package-provided dependencies that differ are part of the candidate treatment, not an isolated SDK-memory source change.
2. **Freeze checks are outside the runner.** run_trial.py:32 records only a post-run executable hash; it does not assert that hash equals prelaunch identity, recheck source/package/module/content/config inputs, or pin the reference before and after. prepare.py's validation is pre-copy and its preparation record does not certify the final copied tree after runtime/launcher activity. Parent must retain pre/post protected-file records and preserve earlier failures. Initial userdata intentionally changes during play: compare fresh prelaunch identities, not final save equality.
3. **The reference comparator's nonzero result needs classification.** run_trial.py:35-50 preserves failures correctly, but reference disagreement and malformed/incomplete evidence both lead to nonzero wrapper exit. A valid 500R/0S old trace differing from the reference is the intended discriminating observation, never a passing reference control. Preserve it, separately establish fatal/coverage/identity validity, and compare old against current directly. Do not stop interpretation at the generic wrapper exit or silently continue after fatal/incomplete evidence.
4. **A generic mismatch is not specifically RNG divergence.** bounded_trace_cmp.compare reports only the first differing frame; it compares the entire captured fighter body. Parent must retain earliest frame, slot and differing named fields (`rng`, `rngcalls`, entry/status/motion/position/damage and optional `w`). Both candidates differing from the original could still be identical to each other. Disabled raw observers mean no exact seed, selector or writer attribution; an RNG fold difference is evidence about the sampled words, not proof of a particular seed value or store.
5. **Use unoptimized Python for these local scripts.** prepare.py's source/package checks and run_trial.py:46's exact count check are Python assertions. `PYTHONOPTIMIZE` can remove them. Record normal interpreter operation (`sys.flags.optimize == 0`, no optimization environment/flags); do not regard execution under optimization as satisfying those assertions. No shared-tool changes are needed for this bounded review.

The runner now deduplicates inherited environment keys, explicitly zeros all five switches and all listed observers, retains the same executable basename, uses fresh save copies and the same tape/seed, runs the fatal gate first, retains the original reference comparison, and independently requires `real=500,replay=0,passes=500`. These address the initially noted generic comparator limitations. A fatal failure can still produce a diagnostic count file afterward; that file must not override fatal rejection.
