# Input-history hardening implementation split

2026-10-21, root / input_hardening_design. Read-only review of production input, wire, receive/reset and handshake paths. M7.4 remains unfixed; this is an implementation plan, not acceptance evidence.

First, give production input storage an explicit admissible interval controlled by local retention and forward-simulation progress. Its width must be less than RB_RING; remote progress must not choose the retention floor. Replay must not move the interval backward or evict inputs needed by the oldest snapshot. Reject out-of-window insertion before changing real/predicted slots or mismatch state, and return acceptance status so rejected data cannot advance ACK/readiness/progress. Validate local/get arithmetic too, including signed frame overflow. Replace the expected-defect test only after preservation is demonstrated. Cover bounds, reordered gaps, duplicates, prediction, repeated wraps, replay retention and INT_MIN/MAX.

Second, replace epoch handling as one coordinated protocol change. A mandatory versioned envelope must preserve full-width session and match identities through queueing. Negotiate identity independently of deterministic game seeds. Validate under the lock that publishes epoch/reset state, then revalidate at drain before changing pads, ACKs, mode, readiness, checksums or time synchronization. Publish started only after input/reset initialization. Define the scope of pre-match RTT packets explicitly: they currently affect input delay. Bump the handshake protocol and reject legacy untagged/trailer-only packets; no compatibility fallback. Test receive/reset interleavings against actual production policy.

Why both are needed: rb_input_remote_put accepts a future frame that aliases retained input. rb_net validates only present epoch trailers, then strips them before queueing. A packet can validate before reset and enqueue after its flush, leaving drain unable to revalidate identity. The eight-bit tag also collides, and malformed PADS can affect peer mode before parsing. A larger tag alone does not repair these paths. Packet size limits and signed wire arithmetic need explicit regression cases.

M7.4 closes only after both parts and independent review. Compatibility digests and seeded initial-state agreement remain separate M7.7/M5.2 work. The source-hardening priority remains M7.8 → M7.1 → M7.3 → M7.2; this disjoint network plan is ready when implementation ownership is available.
