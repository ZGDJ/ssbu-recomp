## Transaction change

After acquiring the existing preparation locks, `rgc_prepare` starts with the locked current catch table and overlays the prospective bytes from `RestorePlan.pages`. Partial intersections are supported; the table need not be page aligned or fully captured. Null sources zero the intersecting bytes, the decommitted sentinel leaves bytes unchanged, and the window-one decommitted/null skip matches the actual copy loop. Guarded reads and overflow checks reject unavailable prospective bytes.

Prepared suspended fiber actions supply the stack ranges whose catch records must come from the restored image. Other records come from the current image, subject to the existing dead-stack filter. All removals and insertions occur in a separate fixed-size table using the same production slot-selection and tombstone-removal policy. Exhausting the probe window returns refusal before destructive copying or history changes. Preparation changes neither the live table nor published catch diagnostics. Abort releases ownership without publishing the candidate.

Commit copies the prepared table and publishes prepared diagnostics and trace classifications. It performs no capacity search, inventory enumeration or new lock acquisition. The existing locks remain held through commit or refusal cleanup and observation, then release before unpark. Fixed scratch storage avoids new transaction-time allocation. Normal catch entry retains its legacy overwrite policy; this packet changes ring restoration.

The prepared table has the same intended merge semantics as the prior post-copy repair, including the inherited use of full saved stack bounds for suspended actions. This does not establish complete writer quiescence, validate private Windows fiber layouts across systems, resolve raw-state replay divergence or qualify online compatibility.
