## Implementation and upstream comparison

Pinned upstream `c7c874977ea7510c291ec8c278a58883a2f4e368` publishes the requested worker count before creating unchecked events/threads, drops thread handles immediately and ignores dispatch/wait/completion errors. The revised `runtime/r1_state.c` publishes the count only after all requested workers exist. Creation failure signals stop, joins every created worker, then closes all acquired handles before selecting permanent main-thread fallback. A worker checks stop before reading the batch partition. Interlocked stop state and Windows event synchronization protect startup cleanup and batch handoff under the inherited single-main-thread caller contract.

Successful workers and their handles remain process-owned. Priority is a best-effort performance hint. Worker waits/signals, main dispatch/completion and startup cleanup failures take a logged process abort. Once a batch can have written destination bytes, no failure returns success or clears its queue. Copy partitioning, the 64-job parallel threshold and successful copy/compare/conditional behavior remain inherited. This deliberately changes unsafe OS-failure behavior under ADR-0007, not battle semantics.
