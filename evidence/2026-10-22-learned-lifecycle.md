# Learned protection transition lifecycle

M7.8 continuation after [thread/protection resources](2026-10-22-thread-protection.md). The earlier rejected proposal remains archived, uncompiled and unexecuted under ignored `artifacts/local/learned-transition-proposal`. This implementation instead closes callback admission and drains admitted callbacks before setup, teardown or optional decay changes protection metadata. OFF fault observers also retain admission through their protection query, preventing activation during that query. Admission has checked count/publication invariants and a ten-second bounded fatal wait. This is callback ownership, not proof of guest-writer quiescence.

`ls_open` retains state 1 after a failed initial writable transition without publishing learned membership. Host and VEH opening failures terminate. Commit and decommit transitions serialize against opening through state 3. Commit notifications on absent pages are allowed because the SDK notifies even after allocation failure; failed transitions on committed pages terminate. Decommit notification precedes `VirtualFree`, so absence is checked rather than assumed. Full-page queries validate return size and address geometry; malformed host spans terminate before iteration. Teardown clears a readonly state only after successful reopening or verified absence, and publishes OFF only after successful cleanup. Immutable retained learned geometry replaces collection's mutable window pointer for page addressing. Successful page selection and retained backing remain unchanged from the pinned upstream model; these checked failure and admission semantics are deliberate changes from upstream `c7c874977ea7510c291ec8c278a58883a2f4e368`.
