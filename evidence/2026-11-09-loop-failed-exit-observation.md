## Claim and bounded selection

Lane/profile-to-fighter association is needed to say which fighter a particular consumed lane/profile controls, and for the current frozen mapping contract's independent-player attribution. It is not needed merely to observe two lanes' consumed values, a lane1 mismatch or the correction/load/replay path. A narrower comparison could report fields at two declared discovery-slot indices without claiming controller attribution. That does not establish the same fighter identity across arms or full gameplay correctness.

Source: `rbg_pad` in `runtime/rb_rollback.c` passes HID port id directly to `rbn_pad`. `fh_hook` in `fighter_sdk/fighter_host.c` assigns slots by first-seen BOMA and caches entry separately; a missing entry constant leaves e=-1. The BOMA registry provides identity within that process, not an independently proven cross-process lane/profile association. `compare_correction` in `tools/analyze_loop_correction.py` contrasts selected gameplay fields by slot. No supported association getter/consumer is established by these paths. Current final-arm requirements stay binding: this increment adopts no narrower replacement, inferred association, synthetic B/P/read counts or native calibration. Calibration policy/observer remain the next mapping work.

Selected concrete failure: `WindowsNative` can prove exit and then raise `NativeProcessError` on receipt/cleanup failure. `run_admitted` consequently skips its normal verify_after callback and retains exclusion. Reusing verify_after or synthesizing CompletedProcess would misrepresent the stopped attempt. The [component packet](2026-11-05-loop-packet-components.md) explicitly requires independent failure collection here. Stopping condition for this trial: one source-tested collection seam, with durable partial observations and unchanged refusal/lease behavior. This is one driver integration increment, not a complete native packet.

## Implementation and integration contract

`tools/loop_owned_boundary.py` accepts an optional trusted failure_observer. Only the supplied, already verified process module's actual NativeProcessError class with child_created=True, exit_proven=True and an integer return code invokes it. Unknown lifetime, no-child exceptions, malformed diagnostics and other exception classes do not authorize collection. The same final-creation freshness closure and NativeNotCreated identity are preserved. After collection it rethrows the original native error; an observer exception is retained on that error as failure_observation_error. Even a zero child exit cannot become success through this path.

`PacketIdentity.observe_failed_exit(arm, error)` reuses the scope authenticated at successful verify_before. It retains the immutable rehash/comparison, each independently readable frozen file and directory (including prerequisite companions and userdata), graphics cache and attempted full battle identity. A failed prerequisite/read/capture cannot suppress the remaining independent reads. Existing verified-byte execution refuses drifted identity helpers. The record is published in failure_observations before I/O, remains separate from postidentities and blocks later verify_after for that arm.

The method writes failed-exit-observation.json exclusively under the arm's trial directory, flushes and fsyncs it, and leaves existing/partial bytes consumed. Persistence errors remain in memory and propagate to the adapter without replacing the native error. An observation file is a failure record, never readiness or postidentity acceptance. If writing fails, the parent must retain/export the in-memory record and original exception chain; no tool can guarantee durable evidence on an unavailable filesystem.

Parent wiring: supply a trusted callback equivalent to partial(identity.observe_failed_exit, arm) to native_factory's failure_observer, using the same verified admission/process module objects. Freeze/pin the callback, adapter and identity source with driver diagnostics. The full driver must still collect separate fatal, original-reference, fixture/menu/RNG, sealed-trace and normal postidentity gates, consume/stop the journal and preserve the lease. The callback has no release, retry, launch or journal-advance capability. Direct-child waiting still does not prove arbitrary descendants exited; the actual game executable must remain the direct child.
