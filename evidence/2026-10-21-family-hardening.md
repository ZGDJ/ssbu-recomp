# Guided setup hardening and save integration

- Date / author: 2026-10-21 America/New_York, Codex. Task: M0.8, optional-save integration with M0.11; FSD-011/FSD-012. M0.9 clean-PC qualification remains open.
- Baseline: installer branch `5e2bb9b`; integrate the existing family save helper from `a467d80` without importing unrelated runtime edits. This evidence accompanies the hardened source revision.
- Save flow: the wizard requires explicit opt-in and a separate save ZIP. Layout validation precedes the build; save staging/import follows successful game installation. Prior progress is backed up. Updates do not import saves. Import Save refuses unfinished setup/update state, and the importer refuses a pending game save journal. The play launcher blocks unfinished setup/save/update markers.
- Cancellation: a Windows job owns the gated worker and inherited child tools; no worker work begins before assignment. Cancel terminates that job, and the wizard waits for both worker exit and zero active descendants before Retry. Job handle closure also stops children after wizard termination. Elevated LLVM fallback is refused in family mode because it would escape this containment. Job behavior follows the [Windows job object contract](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).
- Observability: last-log-activity age, explicit quiet-period status, bounded live log, and completion polling independent of log reads. Save support ZIP and Collect Logs.bat collect allowlisted bounded/redacted logs and basic revision/OS/disk data without Python. No game files, saves, keys or automatic uploads. Redaction is best-effort; users review reports. Log exclusions/read failures are recorded.
- Recovery: private Python stages and verifies before publishing, preserving old/incomplete runtimes. Bootstrap uses bounded retries and timeouts. Tool/runtime downloads use bounded socket idle/total deadlines, pinned hashes and atomic publication. Interrupted tool stages are preserved with checked paths; no recursive cleanup was added. Game import reclaims only known partial files before its free-space check, and rechecks the reserve during extraction. Save staging checks disk space. Folder preflight checks writability/local non-linked ancestors. Existing hardware checks run before long game import.
- Native UI: resizable scrollable layout, tested at a 560x400 client viewport with 1.5x enlarged controls. Rendered actual Windows Forms UI inspected locally; all controls reachable. This is not certification of every display DPI.
- Automated validation: `python -m unittest discover -s tests -p 'test_family*.py' -q`; `python tests/test_install_download.py -q`; bootstrap PowerShell smoke is also wrapped by family discovery. Synthetic archives and subprocess workers only; actual worker tests replace only Desktop COM operations/process discovery and run real Python venvs.
- Real fresh bootstrap: copied bootstrap script and requirements into a new temporary folder with no existing private Python. `bootstrap.ps1 -NoLaunch -PrivateOnly -NonInteractive` downloaded pinned Python 3.13.16 and pip, installed pinned dependencies (some wheels came from the local pip cache), and final imports of numpy/lz4/zstandard/PIL/unicorn/capstone/Crypto passed, exit 0. Nothing installed system-wide. The preserved temporary runtime path is recorded only under ignored artifacts/local.
- Hardware precheck on this machine: Windows, CPU, RAM, disk and Vulkan-loader checks passed. Codec availability remained a warning. Loader presence is not a real graphics/game performance qualification.
- First failures/review fixes: OneDrive-ancestor preflight correctly refused a fixture placed under a reparse-point ancestor, so native test fixtures use ordinary temporary directories. Independent review caught save-journal replay risk, cancellation dialog completion race, child-termination barrier and log-read completion blockage; all were addressed. Earlier wizard evidence records exit-code handling fixes.
- Scope limits: no complete game-backed installation/launch on a separate clean PC, no two-version real-game update trial, and no claim that hardware/runtime compatibility is proven by source fixtures. A GitHub branch update is distinct from publishing a GitHub Release. Saved diagnostic fixtures/previews remain ignored under artifacts/local; no private game or save data is committed.
