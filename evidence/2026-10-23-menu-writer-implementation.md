## Decision and scope

Between two validated samples on the poll thread the global xorshift128 state at actual `0x71052391c0..cc` advances 78 recurrence steps (130 in the long wait) with no observed executor; the guarded helper `0x710137bc30` is already rejected. The smallest observation that distinguishes a poll-thread inline consumer, an asynchronous consumer on another guest thread, a different pointer path, a host-runtime writer and an observation gap is a hardware write watch on exactly those four words during the existing begin/confirm interval, recording every trap with its thread, word mask, post-store native RIP, return-address slot and sequence tick, bracketed by two further checked samples. Known inline store sites (`f_7101379460`, `f_710141c640`) remain alternatives, not executed evidence; the hypothesis review's bounded census found about 125 inline store sites in about 100 functions plus about 60 helper-call sites, so attribution must be exact, not nearest-function.

`SSBU_RNG_MENU_WRITER_PROBE=1` (exact literal) requires the validated menu prerequisites, refuses fatally when `SSBU_DEBUG_WATCH`, `SSBU_DEBUG_WATCHENTRY`, `SSBU_DEBUG_RESEARCH`, `SSBU_RB_NET_WATCH`, `SSBU_RB_WRITER_PROBE` or `SSBU_RNG_MENU_CONSUMER_PROBE` is set, when `SSBU_RB_SIM`, `SSBU_R1`, `SSBU_RB_NET`, `SSBU_RUNAHEAD` or `SSBU_LS` is not `0`, when a debugger is present or when the vectored handler cannot register. The existing `SSBU_RB_WRITER_PROBE` is untouched and incompatible (unrelated addresses, rollback simulation).

## Mechanism

- Arming after the validated begin sample: a helper thread enumerates every thread, keeps an opened handle, skips threads that already own debug registers (listed, never touched) and installs four write-only four-byte watches (`Dr7` RW/LEN `dddd`, local enables `55`). The poll thread is covered because it waits for the helper. A checked `rng_armed` sample follows the join. Guest threads created during the interval are admitted while still suspended in `os_StartThread` and `pt_create`; admissions are buffered and printed at collection.
- Handler: `EXCEPTION_SINGLE_STEP` with the owned signature (RW/LEN pattern and the four addresses) and a word bit in `Dr6`; no allocation, logging, target reads or unwinding; records thread, phase, RIP, mask, published tick and the qword at RSP (guarded by the TEB stack bounds) into a 4096-record buffer with a 2048-per-thread cap (fixed table claimed by compare-exchange); a cap or buffer hit disables that thread and counts; outside states arming/armed, and after any recording when the state has left them, it clears its own context's watch so a cleanup write is never undone by a returning handler. Trap-flag steps and traps without a word bit are passed on.
- Confirm side: before the menu's checked read only a `rng_disarm` sample, the atomic armed→disarmed flip and `events_before_confirm`. After the confirm sample line: a 100 ms drain, cleanup over the kept handles (`cleaned`, `already_clear`, `foreign`, `missing`, `skipped`), a verification snapshot over every thread (`uncovered`, `leftover`), handle release, then the deferred `event`, `admit`, `collected` and `seal` lines. Statuses: `incomplete` (helper not joined, cleanup failure, pending, inflight, admission failure, foreign, leftover), `truncated` (dropped or capped), `partial` (skipped, admission accounting, uncovered, missing), else `collected`. Any menu unusable transition cancels, cleans up and prints `unusable`.
- Record gate `tests/rng_menu_writer_analysis.py`: exact lifecycle installed, begin, armed, confirm, events, admits, collected, seal; counters must agree with records; `truncated`/`incomplete` are unusable; `partial` needs a coverage reason and vice versa; distances begin→armed, armed→disarm, disarm→confirm, begin→confirm (bound 10000); per-thread totals, +0-word store counts, tick histogram, mappable flags; a freeze-watchdog dump between begin and confirm marks `perturbed` and makes a zero-event packet unusable; `after_confirm` events are excluded from attribution. Production bounds and the refusal list are required on gameplay logs.
- Offline exact mapping `tools/map_menu_writer_event.py` with `tools/dwarf_inline.py`: module classification {game DLL, NRO DLL by membership of `build/work/nro_bin_eh_o2`, host}; for the game DLL, the shipped `obj_eh_o1/c_NNNN.obj` function containing the candidate is disassembled, the runtime bytes must equal the object's, the instruction ending at `fn_offset` must be a store to memory, the unit is recompiled with the actual `build_opt.py` recipe (`-O1 -ffp-contract=off` with force-inlined helpers, the plain ladder, or whole-file `-O0`) plus DWARF 4 line tables and an untouched header, the function must be byte-identical to the shipped object, and the DWARF inlined-subroutine chain at the store names the inlined store helper and the generated `L_<address>` statement that called it. A trap whose RIP lies inside an out-of-line store helper is reported `helper_landed`; when the helper is a frameless leaf (`-O1` units with helpers not inlined) the event's `ret` field, the qword at RSP, is the return address and the call site in the caller is mapped the same way (the instruction ending there must be a `call` relocated to the helper, in a byte-identical recompilation); when the helper has a frame (`-O0` units) `ret` is the homed argument and the caller stays unresolved (round 4). Every step is hashed; any failure is "unmapped". An earlier technique that turned the store helpers into macros was retired after the trial showed it changes code generation for one writer function.

## Validation

Command: `deps/python/Scripts/python.exe tests/test_rng_menu_writer_probe.py` (four tests). Exact-source fixture with real debug registers on dummy words through the compile-time base override, O1 and O3: 18 good cases (zero, write-main, write-other, write-twice, admit, admit-outside, pre-arm-write, post-seal-write, skip-partial, admit-during-arming, write-during-arming, multiword, thread-exits, uncovered-host-thread, admit-foreign, write-after-disarm, tick-at-write, trap-flag), 9 fatal refusals (conflicting modes including `SSBU_DEBUG_RESEARCH`, version, prerequisite, menu disabled, restart, handler registration), 15 unusable cases (order/tick/thread/interval faults, missing or late close, menu unusable while armed, injected OpenThread/snapshot/SetThreadContext/GetThreadContext failures, admission failure, 300-thread bound, in-flight handler, injected leftover), `overflow` on a limit-64 build and `capped` on a cap-8 build. Every good and unusable case verifies all fixture threads clear afterwards, including the probe's own verification pass on the arm-failed path; foreign registers are preserved. 63 parser mutations are rejected. The admission-placement test pins both `os_threads.c` seams and the include/start order. Final evidence: `artifacts/local/menu-writer-source/source-xts60r_t/`.

Existing suites with the modified menu header pass: 92 O1/O3 menu cases, 74 O1/O3 consumer cases with 21 mutations and the private fingerprint. Eight O1/O3 sequence-wiring runs show identical sequence state, holds and boundary ticks with the writer tick stubbed after the consumer tick (`artifacts/local/menu-writer-20261023/seq-wiring/`). Mapping self-test (`mapping-selftest.json`): three inlined stores in `f_710141c640` map to `L_710141c6dc`, `L_710141c6f0`, `L_710141c6f0`; a vector store inside an inlined non-store helper, a mid-instruction offset, a non-store instruction, a landing in the out-of-line `wr32` of `c_019e.c` (`helper_landed`), an NRO module and two host modules are refused with explicit reasons; `c_01ad.obj`, `c_019e.obj` and `c_0242.obj` were reproduced byte-for-byte with the untouched header.

A fixture finding: debug registers set on a thread still inside its own start-up are wiped by it; threads alive at arming are long-running and admitted threads are never-run suspended threads, but a host thread created within milliseconds of the snapshot could lose its watch and appear as `already_clear`. The freeze watchdog default is 1 s, not 5 s; both arms pin `SSBU_VK_WATCHDOG=5` and the analyzer flags dumps inside the interval.

Round-1 reviews: the hypothesis reviewer required all-event recording, bracketing samples and a corrected mapping procedure (NRO modules, `-O0` helper landings, store order, the second inline site, the poll thread's origin); the readiness reviewer returned seven blocking items (integration proof, the `SSBU_DEBUG_RESEARCH` hole, admit ordering, confirm-side perturbation, verified cleanup, the watchdog premise, bracketing reads) and the fixture matrix above. Round 2 (digest `19bc33ca…`): readiness accepted; hypothesis found three analyzer/tool defects (the `ret`-based helper mapping, NRO classification by name prefix, word-0 counting across phases), all fixed. Round 3 (delta): both accepted; the readiness reviewer's cap-path label defect and `self_cleared` recommendation were adopted. Final frozen candidate: normalized source digest `2a6b83f8932df748c21a0ff0d3ce1a39b250678fb717e35f139a3dba82155f9e` over 296 entries, 53 review-file hashes (`artifacts/local/menu-writer-20261023/frozen-source-build.json`). The build and the games are recorded in the integration evidence. Round 4 (post-trial): both reviewers re-derived the `positive` classification and the decision from the retained fields with no blocking objection; the hypothesis reviewer showed the `c_0228.c` helper is frameless, so the tool was extended to map it by return address and all 36 sites now map (`artifacts/local/menu-writer-20261023/frozen-source-r4.json`).

## Decision rules for the games

Positive, exactly mapped game-DLL event inside the armed window: nominates that guest function for semantic inspection, with its thread (poll versus named guest thread), per-tick cadence and whether the word-0 store total equals the armed-window distance; coverage limits do not weaken it; changed endpoints or a failed reference stop further arms, not the attribution of an executed store. Host-module event: a runtime writer, itself the finding. NRO-module event: guest code outside the game DLL, mapped in a later packet. Zero events with full coverage and `rng_armed != rng_disarm`: a writer invisible to the watch set during the armed window (coverage/admission investigation, never "no writer"); with `rng_armed == rng_disarm` the change is localized to the arming/disarming gaps. Zero events with any coverage limit, a perturbing dump or a failed gate: a failed observation. No reseeding, reset suppression, hash weakening or new reference follows from any outcome.
