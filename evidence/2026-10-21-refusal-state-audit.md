## Observable contract

`SSBU_RB_REFUSAL_AUDIT=1` audits the first eligible restore attempt only, consuming the allowance before allocating. It copies exact immutable ring data before plan construction: ring descriptors/counters, full index/touch arrays, active free/touch lists, main context, captured fiber data and active slot descriptors, undo entries and fiber/command-buffer snapshot payloads. After plan construction it copies each planned destination's bytes and separately observes physical-page State/Protect. Overlapping logical ranges can produce repeated physical-page observations.

On refusal it compares after page and command-buffer abort cleanup, before unpark. The default path has no byte-copy audit. A successful restoration disposes the audit before destructive rewind and logs `commit_not_checked`; that outcome cannot pass the refusal checker. The old unconditional `unchanged=1` text was removed from generic refusal logs.

This observer has a 256 MiB allocation limit, not an execution-time limit. Metadata comparisons read in 4 KiB chunks and can extend holds. `ReadProcessMemory` is used for bytes; native tests verify that unread guards remain armed. VirtualQuery separately supplies State/Protect. Budget failure or unread state yields incomplete coverage. The audit does not claim quiescence, and changed guest bytes remain observations rather than unconditional corruption assertions.

Excluded: dirty maps, learned membership, live command-buffer objects, blanket pool/flat-shadow source contents, physical residency and thread-hold completeness. Allowed copy/verifier capacity growth is not an invariant. This is exact comparison of the recorded spans, not a complete process snapshot.

This exposed an observer distinction: a wholly reserved, uncommitted destination has no bytes to read. The next schema must explicitly observe that state on the entire logical range and verify the same per-page State/Protect after abort. Guarded, inaccessible, free or mixed spans must remain unreadable failures. Absence-to-bytes or bytes-to-absence is a change even if all committed bytes are zero; merely equal absent counts cannot substitute for per-span comparison.

Version 2 implements that distinction in the shared production/native-test reader: after a byte read fails, it recognizes absence only for page spans whose entire range is MEM_RESERVE. Metadata never receives that classification. `absent_before` and `absent_after` are separate from unexpected unread counters. Per-span status transitions count as changed; OS State/Protect observations remain mandatory. This does not reinterpret v1 logs.
